# Relinker usage

[**Online relinker**](https://boykopovar.github.io/AnyPS5/) - files stay on your device.

### Browser folder output

The online converter can save Linux output as an uncompressed folder in supported browsers. It does not overwrite an existing destination folder. If conversion fails or is cancelled, it aborts the active file and attempts to remove the newly created output folder. If the browser prevents cleanup, the error names the folder that may contain incomplete files.

## Input and conversion

Use a clean ELF executable. Place its bundled ELF modules in `sce_module/`, `sce_modules/`, or `prx/` beside the input executable, or under the parent directory selected with `--sce-module-path <path>`. The option accepts absolute paths and paths relative to the current working directory; do not include the `sce_module` directory itself. Only files directly inside the module directories are processed. SELF/fSELF containers are skipped with a warning; unwrap them before relinking if they need to be included. `tools/unwrap_self.py <input.self> <output.elf>` does that for a decrypted container: it places the segments at the offsets of the SELF segment records and restores `p_offset % p_align == p_vaddr % p_align`, and it refuses a container whose load segments all look encrypted. `prx/` can coexist with either `sce_module/` or `sce_modules/`. Both `sce_module/` and `sce_modules/` present, or all three absent, is an error.

```text
source/
    input.elf
    sce_module/
        <bundled ELF modules>
```

```text
relinker [options] <input.elf> <output>
```

Linux output:

```sh
relinker source/input.elf app.elf
```

Windows output:

```sh
relinker --windows source/input.elf app.exe
```

macOS output (x86-64 Mach-O, which runs under Rosetta on Apple silicon):

```sh
relinker --macos source/input.elf eboot
```

Add `--to-intel` for Intel hosts, or `--to-rosetta` for Rosetta; a title that runs under Rosetta on Apple silicon is relinked with `--macos --to-rosetta`. `--to-intel` rewrites AMD-specific instructions found in the executable and bundled modules; it cannot translate AMD-specific instructions generated by a title at runtime, so such titles require an AMD host. The output format defaults to Linux ELF regardless of the filename; `.exe` alone does not select Windows.

Titles run natively, so the host CPU needs the extensions of the PS5's Zen 2 CPU that compiled code uses without checking, among them AVX2, FMA, F16C, BMI1, BMI2, LZCNT and MOVBE. On Linux and Windows a converted title logs the host CPU's extensions at start-up and stops before running any title code, naming the CPU and the missing extensions, if one is absent ([list](../dev/debt/libkernel.md)).

The executable, registry, Windows import diagnostics, icon and desktop entry output files must not refer to the input executable or a bundled module being converted, including through a hard link or symbolic link. These collisions fail before any output is written. An existing output file can be replaced if it is separate from those inputs.

Use `relinker --help` to print the usage syntax to stdout and exit with code `0` without converting files. The `--skip-sce-module`, `--exclude-sce-module <file>`, `--skip-syscall-check`, and `--lazy-binding` flags are deprecated. If the application runs with these flags enabled, it will be extremely unstable and unsuitable for general use. These flags are only for debugging.

`--trap-sdk-syscall-stubs` is also for debugging. It preserves a runtime failure if a syscall wrapper is called; it does not implement FreeBSD syscalls or make these applications generally safe to run.

## Runtime layout

For an executable that assumes its image starts at `0x400000`, use `relinker --windows --windows-fixed-base 0x400000 source/input.elf app.exe`. This maps its lowest ELF load page there; the PE headers occupy the preceding 64 KiB. Use this option only when the executable requires an exact address. Without it, the Windows executable has no `DYNAMIC_BASE` and loads at its preferred base `0x140000000`; relocations are kept, so Windows relocates it if that range is taken. Modules keep `DYNAMIC_BASE`. This option does not change macOS output.

For an executable that assumes its image starts at `0x400000`, as Ruffle (PPSA68091), VLC (PPSA85300) and XPSemu (PPSA97358) do when they read their `app0/imports.txt`, use `relinker --linux-fixed-base 0x400000 source/input.elf app.elf` on Linux. Use this option only when the executable requires a fixed address. Without it, Linux output is a position-independent executable as before.

The same base is applied to executables selected with `--executable`; bundled PRX modules are not rebased.

Paths are relative to the output executable:

```text
app.elf (Linux) or app.exe (Windows)
libs/
    *.prx
app0/
    <app resources>
    eboot.bin
    sce_module/
        <converted modules>
```

Use `sce_modules/` or `prx/` instead of `sce_module/` if that is the input directory name. Relinker preserves each module's directory under `app0/` and prints its exact path. Place app resources in `app0/` separately, including the title's original `eboot.bin`: titles test `/app0/eboot.bin` to find their own directory, as it is always present on the console (ProsperoTV, ProsperoRadio, ProsperoLight and ProsperoLichess fall back to an empty `/data/homebrew/<title id>` and fail to load their fonts without it). Only the converted executable runs. Copy the built system libraries from `build/core/libs/libs/*.prx` into `libs/`; use libraries built for the target OS. A custom `--rpath` changes the system library location.

Some applications also need their original `app0/sce_sys/param.json` at runtime. AnyPS5 reads this file for the title ID and display name; it must contain a non-empty `titleId` string and a non-empty `localizedParameters` object with a language entry that has a non-empty `titleName`. It selects the entry named by `defaultLanguage` (inside `localizedParameters`, or at the top level); if that entry is absent, it tries `en-US`, then the first object-valued language entry. Preserve the values from the title's own metadata and place the file under the same `app0/` directory as the other app resources. At startup, its presence in the working directory creates `data/`; a non-zero `downloadDataSize` also creates `download0/`. Without the file, neither directory is created. If it is missing or invalid, metadata calls such as title/window setup can fail with a `param.json` error.

Use the generated files printed as `Guest module:` for bundled title modules. `libs/` is for AnyPS5 system libraries, not the original PS5 `.prx` files. Placing an original PS5 module in `libs/` on Windows makes Windows try to load it as a DLL and can fail with error 193 (not a valid Win32 application).

On Windows, a self-built `libs/` also needs `libgcc_s_seh-1.dll`, `libstdc++-6.dll` and `libwinpthread-1.dll` from the `mingw64/bin` directory of the toolchain that built the libraries; the release archives already contain them. The libraries are loaded without searching `PATH`, so a copy elsewhere on the system is not used, and a library that needs one of them fails with error 126 (the specified module could not be found) although its `.prx` file is present.

On Windows, direct memory (`sceKernelAllocateDirectMemory`, up to 13824 MiB per title) is committed when the title maps it, not when the title allocates it or first uses its pages. The system commit limit (installed memory plus page file size, the second value of Committed in Task Manager) must cover the mapped direct memory together with all other committed memory. Otherwise `sceKernelMapDirectMemory` throws `replace guest placeholder with resident direct memory` with the Windows error (`commit direct memory pages` when a page is mapped at a second address, `keep unmapped direct memory` when it is unmapped); enlarge the page file or close other applications.

On Linux, when the Vulkan driver imports dma-buf memory (not the NVIDIA proprietary driver), shared direct memory is imported through `/dev/udmabuf`, and the user who runs the game needs read-write access to it. Many distributions create it as `root:kvm` with mode `0660`: add the user to the `kvm` group and log in again (an ACL such as `setfacl -m u:$USER:rw /dev/udmabuf` lasts until the next reboot). Without access, startup prints `[gpu] open /dev/udmabuf: Permission denied`, these ranges are copied instead of imported, and GPU stores to them through FLAT/GLOBAL addresses fail with `BDA access failed`. A range larger than 64 MiB is imported as one sparse buffer over 64 MiB udmabuf buffers when the device binds sparse memory (RADV, ANV). Without sparse binding, or when the range does not start on the device's sparse block size in the backing file, ranges above udmabuf's `size_limit_mb` (64 MiB by default) are copied as well.

Linux:

```sh
chmod +x app.elf
./app.elf
```

Windows PowerShell:

```powershell
.\app.exe
```

A Windows executable started without a standard output or error handle, such as a `--windows-gui` build started from Explorer, writes that output to `anyps5.log` beside it, replacing the previous run's file. Without write access to that directory it runs without the log.

### Controller input for test runs

Set `APS5_PAD_INPUT_FILE` to an absolute path before launching the application to enable controller pulses from a local command file. Once the application is reading controller input, send a button with the helper from the repository root:

```sh
APS5_PAD_INPUT_FILE=/tmp/anyps5-pad ./app.elf
python3 tools/pad_input.py /tmp/anyps5-pad cross
python3 tools/pad_input.py /tmp/anyps5-pad down --hold-ms 500
python3 tools/pad_input.py /tmp/anyps5-pad release
python3 tools/pad_input.py /tmp/anyps5-pad release --left-stick 128 0 --hold-ms 2000
python3 tools/pad_input.py /tmp/anyps5-pad cross --left-stick 255 128 --right-stick 0 128
```

Run the helper in a second terminal. Commands are polled at most every 100 ms during controller reads, and their buttons add to physical controller input. A press lasts 300 ms by default, starting when the application reads it, and releases automatically; `--hold-ms` accepts 1–5000 ms. `--left-stick X Y` and `--right-stick X Y` hold the sticks for the same time: each axis is 0-255, 128 is the centre, X grows to the right and Y grows downward. While such a command is active both sticks come from it instead of the physical controller, and a stick that was not named stays centred. Wait for the application to observe a release before sending another press. The file holds only the latest command; rapid commands can replace one another. Commands left over when the application first reads the controller are ignored. Without the environment variable, file input is disabled.

### System fonts

Games that open the console's system font sets (`sceFontOpenFontSet`) need font files in an `anyps5-fonts/` directory beside the output executable; set `ANYPS5_SYSTEM_FONTS` to use another directory. Files dumped from the console are used under their own names (`SST-Roman.otf`, `SST-Bold.otf`, `SSTJpPro-Regular.otf`, ...). Without them, these openly licensed substitutes are used when present: `NotoSans-{Light,Regular,Medium,Bold}.ttf` and `NotoSans-{LightItalic,Italic,MediumItalic,BoldItalic}.ttf` (Latin and Vietnamese), `NotoSansMono-{Light,Regular,Medium,Bold}.ttf` (typewriter), `NotoSansThai-{Light,Regular,Medium,Bold}.ttf` (Thai) and `NotoSansCJK-{Light,Regular,Medium,Bold}.ttc` (Japanese and Chinese). Without either, opening a system font set fails and the game shows no text in those fonts.

### Console language

Games ask for the console's language with `sceSystemServiceParamGetInt` and show their text in it when they have it. It is English (United States) unless `ANYPS5_LANGUAGE` is set to another console language number: 0 Japanese, 1 English (United States), 2 French, 3 Spanish, 4 German, 5 Italian, 6 Dutch, 7 Portuguese (Portugal), 8 Russian, 9 Korean, 10 Chinese (Traditional), 11 Chinese (Simplified), 12 Finnish, 13 Swedish, 14 Danish, 15 Norwegian, 16 Polish, 17 Portuguese (Brazil), 18 English (United Kingdom), 19 Turkish, 20 Spanish (Latin America), 21 Arabic, 22 French (Canada), 23 Czech, 24 Hungarian, 25 Greek, 26 Romanian, 27 Thai, 28 Vietnamese, 29 Indonesian, 30 Ukrainian. For example, `ANYPS5_LANGUAGE=21` selects Arabic. An empty value is the same as an unset one; any other value stops the game at its first language query with an error that names the variable.

### GPU selection

The game runs on the first Vulkan 1.1 device with graphics and compute queues and swapchain presentation, preferring a discrete GPU over an integrated one. Set `ANYPS5_GPU` to a part of a device name, compared without regard to case, to run on another device; the names are printed at start-up in the `Physical device candidate` lines. When no usable device contains the text, the start fails and the error lists the device names.

The window presents with vertical sync (`fifo`). Set `ANYPS5_PRESENT_MODE` to `fifo_latest_ready`, `mailbox` or `immediate` to keep the game from waiting for the display: `fifo_latest_ready` and `mailbox` still show whole frames at the display's refresh and drop the ones in between, `immediate` presents at once and can tear. The start fails on any other value and when the surface does not offer the mode (`fifo_latest_ready` needs `VK_KHR_present_mode_fifo_latest_ready` or its EXT form). Flips stay paced at 59.94 Hz in every mode. A Wayland compositor can stop delivering frames to a window it does not show, for example one on another workspace: on Hyprland with the NVIDIA driver a `fifo` swapchain then presents about once per second, while `fifo_latest_ready` and `immediate` keep the game at its normal rate.

On Windows, the OpenCL, OpenGL, and Vulkan Compatibility Pack can install Mesa Dozen, which exposes D3D12 devices through Vulkan. Some D3D12 drivers can crash while the Vulkan loader enumerates adapters, even when AnyPS5 would select a native Vulkan device. If this happens and the system has another Vulkan driver, disable Dozen for the current PowerShell session before launching AnyPS5:

```powershell
$env:VK_LOADER_DRIVERS_DISABLE = '*dzn*'
.\app.exe
```

Do not disable Dozen if it is the only Vulkan driver available; the application would have no device to use. `VK_LOADER_DRIVERS_DISABLE` matches Vulkan driver manifest filenames and requires a Vulkan loader built with headers 1.3.234 or later ([loader documentation](https://github.com/KhronosGroup/Vulkan-Loader/blob/main/docs/LoaderInterfaceArchitecture.md#filter-environment-variables)).

On Windows, NVIDIA driver 610.47 can crash in its shader compiler while pipelines are created: the log ends in `FATAL: unhandled exception 0xc0000005` with `nvgpucomp64.dll` in `rip`, on a driver thread. PPSA25344 on an RTX 3060 stopped this way in 3 of 3 New Game loads, also with `APS5_NO_PIPELINE_LTO=1`; with driver 617.42 the same build and scene ran for 40 minutes. Update the driver when the crash is in `nvgpucomp64.dll`.

### HDR output

HDR output is available on Windows only. Titles see it when the monitor showing the window runs in HDR mode (Settings > Display > Use HDR), the window's Vulkan surface offers an HDR10 (`VK_COLOR_SPACE_HDR10_ST2084_EXT`) swapchain in a 10-bit format, the instance has `VK_EXT_swapchain_colorspace` and the device `VK_EXT_hdr_metadata`. The monitor's luminance comes from DXGI; a monitor that reports no peak luminance is taken as 1000 nits peak and full-frame, 0 nits black. On Linux and other hosts the output is always SDR, because the surface's formats do not show whether the display is in HDR. A title's BT.2100 PQ display buffers then reach the display unchanged; without HDR output they are converted to SDR.

### Shader cache

Recompiled shaders and the Vulkan pipeline cache are kept in a `shader_cache/` directory beside the output executable, so later runs skip recompilation. Set `ANYPS5_SHADER_CACHE_DIR` to use another directory, or set `ANYPS5_NO_SHADER_CACHE` to any non-empty value other than `0` to disable both caches. Shaders are stored in a subdirectory named after the recompiler's source version; subdirectories of other versions unused for 14 days are removed the first time a run looks up a shader. The pipeline cache is one `vk-pipelines-*.bin` file per GPU and driver version. Deleting the directory is safe: it is rebuilt on the next run.

The cache is kept in layers: resource plans live in a `plans-<version>/` subdirectory named after the recompiler's front end only, so a build that changed only the SPIR-V emitter keeps them, and a new driver starts from the pipeline cache an earlier driver with the same pipeline cache UUID wrote. `APS5_SHADER_CACHE_V2=0` keeps everything under the full source version and starts every driver version with an empty pipeline cache. `APS5_VERIFY_SHADER_CACHE=1` prepares a fresh plan for every cached one and stops the title when they differ. The creation recipes of compute pipelines are kept in `pipeline-recipes/` for prewarming (see Shader compilation).

### Shader compilation

Vulkan pipelines are compiled on a scheduler that runs the work a queue is waiting for first. Each switch below is on unless it is set to `0` (`legacy` for the scheduler); switches that depend on another one are off when that one is off.

- `APS5_COMPILE_SCHEDULER`: the priority compile scheduler. A pipeline a draw or dispatch needs now goes ahead of pipelines compiled ahead of use, and one worker is kept for it. `APS5_COMPILE_WORKERS` (a quarter of the logical processors, 2 to 8) sets the number of compile threads and `APS5_COMPILE_BUDGET_MIB` (2048) the memory that speculative compiles may reserve. `legacy`, or `APS5_LOCKED_PIPELINES`, builds pipelines on the thread that needs them.
- `APS5_COMPILE_PARK`: a draw or dispatch whose pipeline is still compiling gives up its queue's turn instead of blocking the queue worker, and continues when the pipeline is ready.
- `APS5_PIPELINE_COMPILE_AHEAD`: the compute pipelines of dispatches queued behind the one running are compiled ahead, after the pipelines a queue is waiting for.
- `APS5_PIPELINE_CONTENT_DEDUP`: compute shaders whose pipelines would be identical share one pipeline.
- `APS5_PIPELINE_PREWARM`: the compute pipelines of earlier runs are compiled again when the device starts, before the title asks for them (needs `APS5_PIPELINE_CONTENT_DEDUP`).
- `APS5_SPIRV_INTERN`: identical compiled shaders are kept in memory once.
- `APS5_PIPELINE_CACHE_PROBES`: before a draw or dispatch waits for its pipeline to compile, the driver is asked to create it from the Vulkan pipeline cache only; a pipeline an earlier run compiled is then used at once (needs `VK_EXT_pipeline_creation_cache_control`).
- `APS5_PARTIAL_GROUPS_AHEAD=known|all|none`: which compute shaders also get their partial-thread-group variant prepared ahead of use. `known` (the default) prepares it only for shaders an earlier run dispatched with partial thread groups (recorded in `shader-use.bin`); others prepare it at their first such dispatch. `all` prepares it for every compute shader, as before, which roughly doubles cold preparation work.
- `APS5_SHARED_BUFFER_HELPERS`: formatted buffer accesses of all buffers share one function per access shape instead of one per buffer, which keeps compute shaders with many buffers smaller before specialization.
- `APS5_OUTLINE_IMAGE_MODES`: an image access that depends on the image's run-time format calls one function per image instead of repeating every format's code at each access, which keeps very large compute shaders several times smaller.

Off by default: `APS5_VERIFY_COMPILE_JOBS=1` checks that every shared or prewarmed pipeline was built from the recipe the draw or dispatch asks for, and `APS5_VERIFY_SHADER_EMISSION=1` compiles each shader in its alternative forms and stops the title when their interfaces differ. `APS5_COMPILE_TRACE=<file>` (or `1`) writes one JSON line per compile step with its timing.

### Storing GPU results at each flip

GPU results in storage images and render targets stay on the GPU until something reads their memory. A title that frees such an image after waiting for its GPU work and reuses the memory can have its new data overwritten when the results are stored later ([TechnicalDebt](../dev/TechnicalDebt.md)). `APS5_STORE_AT_FLIP=1` stores every pending result when a display buffer is flipped, at the cost of one write-back per pending image and frame. `APS5_STORE_AT_FLIP=shadow` stores them the same way but leaves the stores in the device-local unit shadows, which reach guest memory when a read the driver sees (a CPU access through the flush hook, a copy, a scanout) asks for them: a title's own CPU loads do not see them. Any other value stops the title at its first flip.

A title's own CPU reads of that memory are not seen, so a title that waits for a GPU label and then reads the results reads stale memory. `APS5_STORE_AT_LABEL=1` stores every pending result before each label the GPU writes (`RELEASE_MEM`, `WRITE_DATA`, `DMA_DATA`), at the cost of a write-back of every pending image per label. Any other value stops the title at its first label.

### Guest-memory coherence checks

Each switch below takes `0`, `1` or `verify`. Any other value stops the title when the GPU device is created.
- **Off by default:** `APS5_COHERENCE_AUDIT`, `APS5_COHERENCE_ORDERING`, `APS5_COHERENCE_DIRECTORY`.
- **On by default (`1`):** `APS5_COHERENCE_FAULTS`, `APS5_COHERENCE_INPUT_LEASES`, `APS5_COHERENCE_RESIDENCY`, `APS5_COHERENCE_LAZY_RELEASE`, `APS5_DEFERRED_POINTER_STORES`. Set one to `0` to turn it off.

The protection switches take effect once the GPU device installs the access guards, on Windows only. On other systems they stay inactive, except that `verify` stops the title.

`APS5_DEFERRED_POINTER_STORES=1` (the default):
- **Before any address-based shader:** only the unit shadows over its heaps are published, so the storage images pending there are no longer retiled to guest memory first.
- **Pointer writers:** a shader that may store through pointers is tracked until it completes. A flip or address-based store of an image older than such a shader over its memory waits for a later flip. Any other store of that image first waits for the shader, so its stores are never overwritten by older results.
- **Readers:** a shader that only reads through pointers can still see host bytes under an image whose newer results are pending.
- **`0`:** stores every pending image over the heaps before each address-based shader, at the cost of tens of GB per 10 s in heavy scenes.
- **`verify`:** stops the title when such an image would still be written back before the shader completed.
- **Report:** a `[pointer-stores]` line every 10 s counts the deferred stores, the waited write-backs, and the pointer shaders that ran with pending images over their heaps.

`APS5_COHERENCE_AUDIT=1` keeps a version for every GPU writer the driver records (address-based shaders that may store through pointers, and written buffer elements) and checks every store of an older GPU result into guest memory (a pending storage image, a unit shadow) against it. The first stale store prints a `[coherence] stale publication` line with the writers and stores that touched those bytes; later ones are counted on a `[coherence]` line every 10 s. An address-based shader that reads host memory under a pending image or an unpublished unit shadow prints `[coherence] stale read`. `verify` stops the title at the first stale store instead. Rendering is unchanged; the checks cost CPU time.

`APS5_COHERENCE_ORDERING=1` changes what the driver stores before GPU work:
- A shader that may store through pointers:
  - its heaps are noted as pending writes, so driver CPU reads of them wait for it;
  - only its color target and the storage images it writes are left pending.
- Every pending result is stored before each label, as with `APS5_STORE_AT_LABEL=1`.

`verify` also runs the audit and stops the title at the first stale store, stale read, or label written while results are still pending.

`APS5_COHERENCE_DIRECTORY=1` makes those checks compare guest bytes by the memory backing them, so a write through one mapping and a store through another mapping of the same memory are compared. `verify` also stops the title when a writer completes after its range was mapped to other memory. This switch is Windows only; on other systems it stops the title at start.

`APS5_COHERENCE_FAULTS=1` makes guest memory whose newest bytes are only on the GPU inaccessible to the title's own CPU code. That covers the whole 4 KiB pages under a pending storage image or an unpublished unit shadow, through every mapping of them.
- **First access:** the first load or store there is held. The driver stores and publishes the GPU results over the range and waits for them, then lets the access proceed. A title reading results after a label, or overwriting part of a GPU result, then sees the right bytes, including a store of a value the old bytes already held.
- **File reads:** kernel file reads into such memory resolve it first.
- **Refused ranges:** ranges the protection refuses (pinned or resident pages) keep the default behaviour.
- **`verify`:** stops the title at a refused or partly covered range, and at a driver access to such memory made while it holds the GPU lock.
- **Mapping changes:** unmapping, decommitting, reprotecting or pinning such memory first stores the GPU results over the whole pages involved, then proceeds.
- **Limits:** Windows only. Each pending image costs a protection change.
- **Driver accesses:** a driver thread that holds the GPU lock and touches such memory does not wait for a title thread already resolving it. It stores the results itself and releases the guard, and the title thread's resolution then finds nothing left to do.
- **During resolution:** the range is read-only while it is resolved. Other threads' loads see the bytes from before, and their stores wait.

`APS5_COHERENCE_INPUT_LEASES=1` protects the guest memory that a recorded dispatch reads in place through host imports, from recording until its batch completes. A native store into that memory waits until the recorded work has run, so the dispatch reads the bytes it was given rather than a later write. The protection covers every 4 KiB page the reads touch, so reads beside the stored bytes wait as well. Address-based heaps are not leased, because their reach is the whole heap. `verify` stops the title when a lease is refused. Windows only. Each dispatch costs a protection change, and the title's stores into memory the GPU still reads wait for the GPU.

`APS5_COHERENCE_RESIDENCY=1` protects the guest memory under device-resident buffer results the same way. While it is active, `APS5_LAZY_STAGING_OUT` defaults to on, so buffer results a dispatch wrote through a staged copy stay on the device instead of being copied back after every use. Results whose pages the guards cannot cover whole are copied back at once, as before. `APS5_LAZY_STAGING_OUT=0` copies everything back. The title's first load or store there publishes those results into guest memory and waits for them before it proceeds. A CPU store over such results then keeps the device bytes around it instead of reaching the unsupported publish after a CPU store. `verify` stops the title when the protection is refused or does not cover whole pages. Windows only.

`APS5_COHERENCE_LAZY_RELEASE=1` makes labels and flips store only the pending results whose memory the native protection does not cover. Protected results stay on the GPU until something reads them, and the title's own CPU accesses resolve them when they happen. Every `APS5_STORE_AT_FLIP` value then behaves the same, and `APS5_STORE_AT_LABEL=1` still stores everything. `verify` stops the title when a label or flip leaves results that are neither stored nor protected. The switch needs `APS5_COHERENCE_FAULTS`, and `APS5_COHERENCE_RESIDENCY` too when `APS5_LAZY_STAGING_OUT` is on; without them the title stops at start.

### GPU queue waits and scheduling

A `WAIT_REG_MEM` on one queue may be satisfied by a label another queue recorded but the GPU has not stored yet. Only labels recorded after the wait became active count, that is after the waiting queue's previous wait (`APS5_WAIT_FLOOR=activation`, the default). `APS5_WAIT_FLOOR=submission` with `APS5_LABEL_TIMELINE=off` restores the older rule, which counts every label recorded after the waiting submission arrived; it is too loose, since a later wait in the same submission can then be satisfied by a value overwritten before it could have seen it. `APS5_VERIFY_WAIT_OBSERVATIONS=1` stops the title when a wait is satisfied by a value it could not have observed.

With `APS5_COHERENCE_ORDERING=1` or `verify`, a label also waits behind the write-backs its batch still owes, so a title's own CPU loads never see a label before the results it releases. `APS5_LABEL_PUBLICATION=ordered` or `early` names the same choice; a value that contradicts `APS5_COHERENCE_ORDERING` stops the title.

In runs with `APS5_PROFILE_DRAW` (as `run.ps1 -Perf` and `-Debug` set it), `APS5_TRACE_WAIT_CHAIN=1` prints a `[waitchain]` line per queue every 10 s. The line splits the time each blocked wait spent into: producer label not recorded yet, recorded but not submitted, submitted but not finished on the GPU, finished but not stored for the CPU, and stored but not seen yet. A `[labels]` line gives the same latencies over all labels. Slow-wait reports name the label that satisfied the wait.

`APS5_QUEUE_SCHEDULER` chooses how the GPU queues' workers take turns:
- `dag` (the default) runs the queues concurrently and lets a packet whose shader is still compiling wait without holding any lock.
- `serial` runs one packet at a time across all queues; the oldest runnable submission goes next, and a queue waiting on a label gives up its turn. It is a reference for comparing results, not a fast mode.
- `off` runs the queues concurrently without the scheduler's bookkeeping, as before it existed.

`APS5_QUEUE_SCHEDULER_VERIFY=1` stops the title when a queue runs a packet out of order or while it is waiting for a compile. With `APS5_PROFILE_DRAW`, a `[scheduler]` line every 10 s counts turns, hand-overs and parked packets whenever the scheduler or its verify mode is on.

`APS5_LABEL_TIMELINE=on` (the default) lets a wait be satisfied by another queue's recorded label only with a proof: the label was recorded after the wait became active and covers every awaited byte, or it is the newest value and nothing wrote over it since. Anything else waits for guest memory. `verify` stops the title instead of waiting; `off` accepts such labels without a proof, as before. A compare function the driver does not know stops the title in both modes. The `[waitchain]` line counts waits by proof.

The wait broker (on by default, `APS5_WAIT_BROKER=0` turns it off) makes a blocked wait sleep until a label is recorded or a batch's results reach guest memory, instead of polling on a timer. It still checks again after at most `APS5_WAIT_BROKER_MAX_US` (default 2000), since stores made by the title's own CPU code wake nobody.

`APS5_QUEUE_TOPOLOGY` chooses the Vulkan queues the driver runs on. The log lists every queue family when the device is created.
- `dedicated` (the default when a compute-only queue family has a free queue) records every guest queue other than 0 on a queue of that family, with its own command recorder. Images and buffers are shared by both families (concurrent sharing), so no ownership transfer is needed. Barriers recorded for that queue lose the graphics stages and accesses it does not have. The work of depth surfaces and multisample targets, which needs a graphics queue, goes to the graphics queue's recorder, ordered both ways against the compute queue; any graphics-only command still recorded for the compute queue stops the title, naming the command.
- `same-family` (the default when there is no such family but the graphics family has two queues) takes a second queue from the graphics family instead.
- Both need timeline semaphores; without them the driver logs why and runs serial. A wait on a label the other queue recorded submits the producer first and makes the waiting queue's next batch wait for it on the GPU. Every batch also waits for the batches the other queue had already submitted, and a record into the other queue's batch orders the two queues around it. `APS5_QUEUE_TOPOLOGY_VERIFY=1` stops the title when a batch is submitted without waiting for a producer it depends on.
- `serial` runs everything on one queue.
- A topology set explicitly but unavailable stops the title, naming the families that exist.

`APS5_BATCH_AGE_US=<microseconds>` submits a recorded batch that holds a label once the label is that old, even if no queue packet or wait asks for it. This keeps a label that only the title's CPU code waits for from staying unsubmitted. The default is 2000; `0` turns it off. The `[labels]` line counts these submits.

### Draw and dispatch recording

Queue 0's draws and dispatches are prepared on worker threads and recorded on a record thread by default. Each switch below is on unless it is set to `0`; switches that depend on another one are off when that one is off. The `APS5_VERIFY_*` switches stay off unless set, and stop the title on the first difference they find.

- `APS5_RECORD_THREAD`: a record thread records queue 0's draws while queue 0 decodes the next packets. `APS5_RECORD_THREAD_DISPATCH` records queue 0's dispatches there too.
- `APS5_PREPARE_AHEAD=<1-64>`: how many records queue 0 may post ahead of the record thread (by default the number of preparation workers, at least 4).
- `APS5_PREPARE_WORKERS=<1-16>`: threads that prepare frozen draws. By default one per efficiency core on a hybrid CPU (16 on an i9-13900K), which leaves the performance cores to queue 0, the record thread and the title's own threads; otherwise half the logical processors less two. Both are capped at 16. `APS5_PREPARE_DISPATCHES` prepares queue 0's dispatches on them too.
- `APS5_PARALLEL_RESOLVE`, `APS5_PARALLEL_REVALIDATE`, `APS5_PARALLEL_TARGETS`: the preparation workers also resolve a draw's inputs, template, pipeline, template proof and render targets; the record thread re-checks them. Verify: `APS5_VERIFY_PARALLEL_RESOLVE`, `APS5_VERIFY_PARALLEL_REVALIDATE`, `APS5_VERIFY_PARALLEL_TARGETS`.
- `APS5_WORKER_SNAPSHOT_COPIES`: the preparation workers copy a draw's input snapshots; the record thread adopts a copy when its memory is unchanged. Verify: `APS5_VERIFY_WORKER_SNAPSHOT_COPIES`.
- `APS5_BINDING_PLAN`, `APS5_INCREMENTAL_BINDINGS`, `APS5_INCREMENTAL_PLANS`: draws read their resource descriptors through a planned walk, and reuse the parts of it whose inputs did not change.
- `APS5_DISPATCH_MOVED_TEMPLATES`: a dispatch whose read-only buffers moved reuses its resource template.
- `APS5_ADDRESS_TEMPLATES`: a draw whose shaders only read guest memory through the address table reuses its resource template while the registered memory is unchanged, instead of building it for every draw; each use stores the storage results its pointers reach first. Templates built on a space with writable, heap or sparse mirrors or copied ranges, and draws that write through pointers, are still built per draw. Verify: `APS5_VERIFY_ADDRESS_TEMPLATES` builds each reused template again and compares the mapped address space, pointer heaps and in-place reads.
- `APS5_DRAW_SNAPSHOT_ARENA` (with `APS5_DRAW_SNAPSHOT_ARENA_EXTEND_KIB`, 1024), `APS5_SNAPSHOT_READ_RANGES`, `APS5_MOVED_WORD_RING`: draw input snapshots are shared between draws, and only the ranges a shader reads are copied.
- `APS5_EPOCH_DIRTY_SET` (with `APS5_EPOCH_DIRTY_SET_WIDEN_KIB`, 256), `APS5_COLLECT_COVERAGE`, `APS5_PRECOLLECT_ON_WORKERS`: write-tracking collects are widened, shared between the threads of a collect epoch and made early on the preparation workers.
- `APS5_DIRTY_RECORD`: a draw that continues a render pass skips the binds that did not change.
- `APS5_CP_READS_OVERLAP`: `SET_SH_REG_INDIRECT`, `SET_UCONFIG_REG_INDIRECT`, `SET_CONTEXT_REG_INDIRECT` and `INDEX_ATTRIBUTES_INDIRECT` read their tables when queue 0 parses them, as the command processor does, instead of waiting for the draws queued before them. Verify: `APS5_CP_READS_OVERLAP=verify` reads each table again after those draws are recorded and stops on a difference.

`APS5_IN_PLACE_DRAW_INPUTS` binds read-only draw inputs through their host imports instead of snapshotting them. It is on by default whenever `APS5_COHERENCE_INPUT_LEASES` is: each input then holds a read lease until its batch completes, so a CPU store into it waits for the draw instead of reaching it, and an input whose lease is refused is snapshotted. Setting it to `1` without the leases binds the inputs unprotected (a CPU store before the GPU reads them is seen by the draw); `0` turns it off.

Off by default: `APS5_CHUNKED_RECORDING=1` records a render pass's draws into secondary command buffers on a recording thread (it costs more than it saves at a few draws per pass).
A completion watcher thread waits on the GPU for the oldest submitted batch with completion actions (end-of-pipe interrupts, labels stored behind write-backs, write-backs) and runs them as soon as the GPU finishes it, so a title's CPU code waiting on an event queue or on such a label is woken without the queue workers polling. `APS5_COMPLETION_WATCHER=0` turns it off; idle workers then poll for finished batches as before. The `[labels]` line counts the watcher's reaps and GPU waits.

### Address-based shader experiments

These switches change how recompiled shaders reach guest memory through addresses and how they handle floating point. Each accepts the values shown; any other value stops the title at start. The optimized form is the default (the value marked as such below); the other value turns it off. `verify` runs the old and the new form side by side and stops the title with a description of the first difference.

- `APS5_BDA_ABI=legacy|radix|verify` (default `radix`): how a guest address is found in the table of mapped ranges (a binary search, or an indexed table).
- `APS5_BDA_RELATIVE=off|on|verify` (default `on`): whether a shader reuses the last range it found for later accesses inside it. `APS5_BDA_RANGE_CACHE=1` is the same as `on`, and with `APS5_VERIFY_BDA_RANGE_CACHE=1` the same as `verify`; setting both switches to different values stops the title.
- `APS5_BDA_INLINE_FAST_PATH=off|on` (default `on`): with `APS5_BDA_RELATIVE=on`, asks the GPU driver to inline that reuse check at each access while the full lookup stays a separate function. The generated code is otherwise identical, so it has no verify mode.
- `APS5_BDA_SPAN_HELPERS=off|on|verify` (default `on`): whether wide reads use a reader specialized for the dwords they use.
- `APS5_BDA_WRITE_NOTES=off|on|verify` (default `on`): whether a shader skips recording a written page it already recorded.
- `APS5_FLUSH_PROOFS=off|on|verify` (default `on`): whether denormal flushes are also removed where a value provably cannot be denormal: loop values that only ever carry flushed values through min, max or selects, NaN-propagation selects, products with constants of magnitude one or more, truncation and rounding, square roots and reciprocal square roots. `verify` keeps the flushes and stops the title when such a value is ever denormal.
- `APS5_LAZY_LOG2_REPAIR=off|on|verify`, `APS5_LAZY_TRIG_SERIES=off|on|verify` (default `off`): whether log2, sin and cos evaluate only the correction they select.
- `APS5_BDA_PLACEMENT=host|device|verify` (default `device`): whether compute shaders that store through addresses (without atomics or coherent accesses) work on device-local copies of the host memory they write, copied back after each dispatch.
- `APS5_SHADER_MANIFEST=<folder>` writes one line per compiled shader with its address and instruction counts; `APS5_SHADER_MANIFEST_SPIRV=all` (or comma-separated hexadecimal addresses) also writes the shaders. `APS5_SPIRV_GUEST_LINES=1` tags shaders with guest program counters for GPU profilers.

### GPU placement and render pass experiments

Both switches are on by default (`1`); `0` turns one off, and any other value than those shown stops the title at start.

- `APS5_DEVICE_UPLOADS=0|1|verify`: whether buffers the driver only writes from the CPU and the GPU reads (address tables, shader data of up to 64 KiB, image table maps, mesh arguments) go to video memory the CPU can write directly, instead of system memory the GPU reads over PCIe. It needs a device-local, host-visible memory heap of at least 1 GiB (resizable BAR); without one the buffers stay in system memory and the `[uploads]` line counts them. `verify` reads each write back and stops the title if it differs.
- `APS5_READONLY_ADDRESS_PASSES=0|1|verify`: whether a draw whose shaders read through addresses but never store through them is treated as reading unknown memory only, instead of also writing it, so it no longer ends the render pass for the draws after it. `verify` keeps the old behaviour and counts the pass breaks only such draws caused, on the `[barriers]` line.
- `APS5_DISPATCH_BARRIERS=0|1|verify`: whether the barrier after a compute dispatch waits until later work needs it. A following dispatch whose buffer ranges and storage images do not overlap what the pending dispatches read or wrote runs without one; anything else (a draw, a copy, a label, the end of the batch) records it first. Dispatches through image tables, with copied or placed writes, indirect arguments or device-memory LDS always record it. `verify` records every barrier and counts the ones that would wait, on the `[barriers]` line.
- `APS5_RESIDENT_MIRRORS=0|1`, `APS5_RESIDENT_BUFFER_MIRRORS=0|1`: whether shaders read guest memory they do not write through device-local copies of its host imports (through addresses, and through buffer descriptors respectively) instead of over PCIe. The copies are refreshed from the title's tracked CPU writes before each batch and after the GPU writes the memory in place. `APS5_RESIDENT_MIRROR_MIB=<n>` bounds their size (default: half the video memory; `0` turns both off), and `APS5_VERIFY_RESIDENT_MIRRORS=1` compares them with guest memory at the start of their batches and reports differences on the `[mirrors]` line.

### Tracing system library calls

Windows only. An executable converted with `--trace-imports` records the calls it makes to the libraries named in `APS5_TRACE_CALLS`, a comma-separated list such as `libkernel,libSceSaveData`, or `all`. Without the variable nothing is recorded. The crash and abort reports then end with the last 64 calls: sequence number, thread, library, import name as the executable imports it (a NID) and the caller's address. They are followed by the 32 most called imports since start-up, with their number of calls.

```
last traced system library calls (APS5_TRACE_CALLS):
  #1 thread 9384 libkernel.prx k+AXqu2-eBc from 0x0000000140010006 app.exe+0x10006
most called traced imports (1 calls in total):
             1 libkernel.prx k+AXqu2-eBc
```

Limits are listed in the [libc](../dev/debt/libc.md) and [relinker](../dev/debt/relinker.md) technical debt.

### Windows crash diagnostics

Set `APS5_CRASH_INDIRECT_MEMORY=1` before launching the executable to include up to 64 bytes from each pointer found in the register memory dump. The report labels each block with its register, pointer offset and target address. Inaccessible, incomplete and executable targets are skipped. This additional dump is disabled when the variable is unset or empty.

## Exit codes

`0`: conversion succeeded or help was displayed. `1`: invalid arguments. `2`: conversion failed; the error is printed to stderr. With `--autorun`, successful conversion returns the launched application's exit code.

## Import audit

[`tools/import_audit.py`](../../tools/import_audit.py) lists the system functions a converted game imports and whether the built libraries provide them, before the game is launched. It needs Python 3 and nothing else.

```sh
relinker --registry source/input.elf app.elf
python3 tools/import_audit.py app.registry.json app.libc.prx.guest.prx.registry.json --libs build/core/libs/libs --modules source/sce_module
```

`--registry` writes `app.registry.json` for the executable and one `app.<module>.registry.json` for each converted bundled module; pass all of them. `--libs` is the directory the `libs` target fills ([build instructions](../dev/BUILD.md)); the exports are read from the built `.prx` files, so the result matches what the loader finds. Imports are counted once per NID and library, and every reference lands in exactly one class:

| Class | Meaning |
|-------|---------|
| `implemented` | A built library exports the NID and its function is not a throwing stub. |
| `stub` | Exported, but the whole function calls `NotImplemented_nid_no_patch`: the game loads and throws when it calls it. |
| `absent` | No built library exports the NID: the loader fails. |
| `module` | The import names a file found in `--modules` (the title's own library), which is trusted to provide it. |

ELF modules in `--modules` are audited regardless of filename: their undefined symbols are classified against the built libraries and the other modules' exports, with the module file named in the report, and the libraries they need must have a file in `--libs` or `--modules`. Ordinary non-module sidecars are ignored; malformed ELF, PE/SELF containers and non-ELF files with module extensions remain errors. The audit reads dynamic tables from ELF section headers or, for sectionless files, from `PT_DYNAMIC` and a SysV or GNU hash table.

Each registry has a companion with the same prefix and the suffix `.needed.json`, listing its host library dependencies, including declared `DT_NEEDED` entries with no imports. Dependencies supplied by converted bundled modules, including their aliases, are omitted. The executable's companion includes host dependencies of its bundled modules. The audit reads these companions automatically; keep them beside the registries. Older registries without companions still work, but cannot report dependencies that have no imports; regenerate them with `--registry` to include those dependencies.

The report also lists needed libraries that have no file in `--libs` or `--modules`, including dependencies with zero imports. These do not increase the import or reference counts. Windows can skip a missing dependency when no import needs it; Linux still needs the file. The audit also lists imports exported only by a library other than the one they name; those resolve on Linux and can fail on Windows.

| Option | Effect |
|--------|--------|
| `--libs <dir>` | Built `.prx` directory. Required; repeat for several. |
| `--modules <dir>` | Directory of the title's own modules; repeat for several. |
| `--source <dir>` | `core/libs/prx` tree that is searched for throwing stubs. Defaults to this repository's. |
| `--names <file>` | NID and name per line, as in `aerolib.csv` from [`tools/nid_names.py`](../../tools/nid_names.py); names the absent imports. Never downloaded; a name that does not hash to its NID is marked. |
| `--json <file>` | Full result, stamped with the repository's commit and whether its tree was modified. |

Exit codes: `0` nothing blocks loading, `1` there are `absent` imports or needed libraries without a file, `2` an input could not be read; the message names the file and the value.

A module registry lists `nid`, `library` and `targetOffset` for each relocation against a function that no other bundled module exports, without the `#` suffix of the executable's NIDs.
